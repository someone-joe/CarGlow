# UI 自动化测试用例（小程序）

> 范围：**P0 主业务用例为主 + 少量 P1 边界**；P2 不覆盖（对齐 PRD 表 5-1 与用户要求）。
> 执行方式：wechatide 官方 automator 工具集（`automation_navigate` / `automation_element_action` / `automation_page_action` / `simulator_screenshot`），已验证可跑通（见 `carwash-mp/test/automator/smoke.sh`）。
> 选择器说明：标注类名的以代码现状为准；未标注的，执行时先 `automation_page_action --action querySelectorAll` 核对再断言（官方失败快表要求，不盲目等待）。
> 数据依赖：标注 `[造数]` 的用例先跑对应接口用例造状态（见接口文档），禁止直接改库。

## 五、执行注意事项

1. **顺序依赖**：UI-C08~C16 依赖接口造数；建议一个「数据准备」步骤先跑接口用例的穿测模板（见接口文档附录）。
2. **截图取证**：每条用例至少一张截图存 `carwash-mp/test/automator/screenshots/`（已 gitignore），失败时附当前页 route 与选择器。
3. **不盲等**：元素等待用工具自带 `waitForSelector`（推荐）或 `wait`（≤10s）；超时先 `querySelectorAll` 核对选择器，不死循环加长等待。
4. **交互边界**：元素交互只用 `automation_element_action`（带 selector）；不用 `automation_viewport_action` 做 tap/input；小程序不走画布坐标。
5. **弹窗阻断**：授权/确认类系统弹窗（如 getUserProfile）需人工介入一次，之后 token 化不再询问。
6. **复位**：涉及下单/格口的用例执行后，按 README 4.2 复位格口与产能，防止后续用例报 B2003。
