## 六、执行注意事项

1. **顺序依赖**：UI-C11~C25、W 系列依赖接口造数；建议先跑接口文档附带的穿测模板造好各状态订单。
2. **runner 结构（已定）**：执行期把 `carwash-mp/test/automator/smoke.sh` 扩为 runner —— `smoke.sh` 只做遍历与汇总，用例按编号落 `test/automator/cases/`（一用例一文件，共用造数/断言/截图 helper）。本目录的用例编号即文件名。
3. **截图取证**：每条用例至少一张截图存 `carwash-mp/test/automator/screenshots/`（已 gitignore），失败时附当前页 route 与选择器。
4. **不盲等**：元素等待用工具自带 `waitForSelector`（推荐）或 `wait`（≤10s）；超时先 `querySelectorAll` 核对选择器，不死循环加长等待。
5. **交互边界**：元素交互只用 `automation_element_action`（带 selector）；不用 `automation_viewport_action` 做 tap/input；小程序不走画布坐标。
6. **弹窗阻断**：授权/确认类系统弹窗（如 getUserProfile）需人工介入一次，之后 token 化不再询问。
7. **复位**：涉及下单/格口的用例执行后，按 README 4.2 复位格口与产能，防止后续用例报 B2003。
